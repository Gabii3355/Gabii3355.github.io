Scientific Literature Assistant

A lightweight Retrieval-Augmented Generation application for asking questions about scientific PDF papers and receiving answers grounded in retrieved evidence with page-level citations.

The project combines local PDF processing and BM25Plus retrieval with Groq-based semantic reranking and answer generation. It was intentionally designed without large local embedding models, PyTorch or FAISS, keeping the environment compact and easy to run.

Project goal

How can scientific papers become easier to query without losing the link to the original evidence?

The application was built as a practical literature assistant: it reads locally stored PDFs, retrieves the most relevant passages for a question, reranks them semantically and generates a concise answer with citations pointing back to the source pages.

01

Ground answers in evidence

Answers are generated from retrieved passages instead of relying only on the language model's general knowledge.

02

Keep the setup lightweight

BM25Plus avoids local embedding models, reducing disk and memory requirements while keeping retrieval transparent.

03

Make sources inspectable

The Streamlit interface exposes the selected passages, retrieval scores and exact PDF page references.

A hybrid local + API retrieval pipeline

Most document processing happens locally. Groq is used only where semantic understanding adds the most value: reranking candidate passages and writing the final cited answer.

Retrieval logic

How a question becomes a cited answer

  1. The user asks a question about papers stored in data/papers/.
  2. The query is tokenized and expanded with related terms such as objective → aim, goal, purpose.
  3. BM25Plus retrieves a larger candidate set and applies local scoring heuristics.
  4. Bibliography-like passages and near-duplicate chunks are filtered out.
  5. Groq semantically reranks the strongest candidates and selects the final evidence passages.
  6. The answer model receives only those passages and is instructed not to use outside knowledge.
  7. Each factual claim is accompanied by a citation such as [paper.pdf, p. 11].

Current evaluation

How well does the current model work?

The current version works well as a compact prototype for targeted scientific Q&A. The strongest aspect is traceability: retrieved passages can be inspected directly, and the answer prompt enforces evidence-based citations. The main limitations are retrieval semantics and PDF text quality.

StrongEvidence grounding

For specific questions, the system usually retrieves passages that contain the information used in the answer.

StrongCitation traceability

Page-level references and expandable source passages make it easy to verify model claims.

GoodSemantic reranking

Groq often improves the lexical BM25 ordering by prioritizing passages that better answer the actual question.

Needs workBroad synthesis

Questions about broad conclusions can still mix detailed results with high-level takeaways if several sections are relevant.

Next steps

What could be improved?

01 · Better semantic retrieval

Move from lexical-only retrieval toward a hybrid approach.

BM25Plus is lightweight and interpretable, but it can miss passages that use different vocabulary from the question. A future version could combine BM25 with embeddings when storage constraints are less important.

02 · More robust PDF cleaning

Improve handling of figure labels, split characters and page artifacts.

Scientific PDFs often contain multi-column layouts, figure captions and broken spacing. Better document parsing would reduce noisy chunks before retrieval.

03 · Question-aware answer strategies

Treat objectives, methods, results and conclusions differently.

Broad questions could benefit from dedicated prompts that prioritize explicit conclusion or discussion passages rather than individual detailed findings.

04 · Formal evaluation set

Measure retrieval and answer quality systematically.

A small benchmark of known questions and expected evidence pages would make it possible to compare retrieval variants using reproducible metrics instead of only manual inspection.
